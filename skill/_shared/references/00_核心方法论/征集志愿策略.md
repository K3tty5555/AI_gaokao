# 征集志愿策略 — AI 志愿规划师补录快速响应

## 什么是征集志愿

征集志愿（补录）发生在各省各批次录取结束后，院校因生源不足向社会公布剩余名额，考生可二次填报。

**核心特征**：
- 时间窗口极短（通常 1-2 天）
- 可选学校范围大幅收窄（仅剩余名额院校）
- 策略从"冲稳保"变成"稳保优先，不冒险"

---

## 触发信号（满足任一即进入本模式）

用户说出以下关键词时立即切换征集志愿模式：

- "征集志愿" / "补录" / "征集"
- "滑档" / "没录到" / "落榜" / "没被录取"
- "第二轮志愿" / "一志愿没录上"
- "还有机会吗" + 已知高考分数语境

---

## 与一志愿填报的核心差异

| 维度 | 一志愿（L1-B） | 征集志愿 |
|------|--------------|---------|
| 时间 | 7 天 | **1-2 天** |
| 选校数量 | 24 条（冲 6 / 稳 10 / 保 8） | **TOP 3-5 所，不铺摊子** |
| 冲档 | 正常设置 | **禁止冲档** |
| 服从调剂 | 可选 | **必须勾** |
| 数据依据 | 历年位次 + 大小年 | 当年征集公告 + 历年位次下限 |
| 核心风险 | 大小年波动 | 时间短填错 / 好学校已满 |

## 征集志愿快速流程

### Step 1：确认基本信息（1 问收完）

> "告诉我：① 你的高考分 + 全省位次；② 哪个批次滑档了（本科特控 / 本科 / 专科）；③ 省份和科类（物理类/历史类）。"

### Step 2：调 query_school，只看稳/保

```bash
GAOKAO_PROV={PROV} python3 skill/_shared/scripts/query_school.py \
  --rank {用户位次} --type {科类} --combo {选科} \
  --min-year {当年} --top 5
```

**只取 `wen`（稳）和 `bao`（保）结果，直接丢弃 `chong`（冲）。**

征集阶段院校降低录取门槛（计划补满压力），实际录取位次往往比历年数据**更松**，稳/保档通常能进。

### Step 3：输出精简报告（不用标准 24 条格式）

```
**你的情况**：{分数} / {位次} / {科类}，{批次}滑档

**征集志愿推荐（全部稳/保，不冒险）**：

1. {院校} {专业组}
   - 往年最低位次：约 XXXXX
   - 本年征集名额：以官网公告为准（见下方查询入口）
   - 建议：**服从调剂必须勾**

2. ...（最多 5 所）

**⚠️ 注意**：
- 征集名额以官网实时公示为准，AI 数据有延迟，**必须自查确认有余额再填**
- 录取概率字段在征集阶段仅供参考（历年数据不反映征集当年实际录取线）
```

## 批次层级处理

征集志愿对应本轮滑档的批次，逐批进行：

| 滑档批次 | 征集目标 | 兜底 |
|---------|---------|------|
| 本科特控批 | 本科特控征集（无则降本科批） | 本科批征集 |
| 本科批 | 本科批征集 | 征集无缘 → 专科批 |
| 专科批 | 专科征集 | 单招 / 自考 |

**原则：先稳住当前批次，不要跨批次跳降。**

---

## 特别叮嘱（每次必说）

1. **不推冲档**：征集失败后基本没有补救，一次机会必须珍惜
2. **勾服从调剂**：征集阶段专业可能极冷门，但进了就是进了，比落榜强
3. **查征集名额要快**：征集公告发布到截止往往不超过 24 小时
4. **征集后还有下一批次**：若本科征集落空，专科批还有机会；不要误以为"彻底没机会"
